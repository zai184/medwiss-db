# database/ - Database Schema & Models

**OVERVIEW**: PostgreSQL 15 schema and SQLAlchemy models. The database is the index of source files (`knowledge_entries`) and guideline passages (`chunks`), not the library itself. The files stay on disk.

## WHERE TO LOOK

| File | Purpose |
|------|---------|
| `schema.sql` | Source of truth. All tables, indexes, triggers, materialized view. Run this to init. |
| `models.py` | SQLAlchemy ORM models. Must stay in sync with `schema.sql`. |
| `seeds.sql` | Test data: specialties, diagnoses, symptoms, users, entries, junctions. |

## CONVENTIONS

**Schema-first**: `schema.sql` is canonical. Update it first, then mirror changes in `models.py`.

**Naming**: German table/column names (`fachgebiete`, `diagnosen`, `symptome`, `titel`, `inhalt`). Junction tables: `entry_<entity>`.

**CHECK constraints**: Enforced at DB level for `role`, `aktion`, `schwierigkeit`. Do not rely only on app-level validation.

**Triggers** (in `schema.sql` only, not models):
- `trg_knowledge_entries_search_vector`: Auto-updates `search_vector` on INSERT/UPDATE using German `to_tsvector` with weighted fields (titel=A, zusammenfassung=B, inhalt=C).
- `trg_knowledge_entries_audit`: Writes to `audit_log` on every DML op.

**Extensions required**: `uuid-ossp`, `pg_trgm`, `vector`.

## ANTI-PATTERNS
- **No faceted search view**. `v_entry_search` / `mv_entry_search` were removed (2026-09-01) when faceted search was replaced by simple keyword search. Do not reintroduce them.
- **Do not modify `search_vector` directly**. It is generated by the trigger.
- **Do not forget junction indexes**: Reverse indexes on `entry_fach(fach_id)`, `entry_diagnose(diagnose_id)`, `entry_symptom(symptom_id)` exist for a reason.
- **Use `zusammenfassung` spelling**. Renamed from the old `zusammefassung` (typo) via migration.
